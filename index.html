UVM · AMBA APB · Synopsys VCS

APB memory: design and UVM verification

I designed an AMBA APB memory slave and verified it with a UVM environment: constrained-random stimulus, a scoreboard, assertions, and functional coverage. Scoreboard failures and VCS waveforms pointed me to protocol and data mismatches; I corrected the RTL or the testbench, then closed coverage.

Self-checking tests

  • Reset behavior
  • Read and write transfers
  • Boundary address and data values
  • Randomized address and data
  • Repeated accesses to the same location
  • Write followed by read, checking data integrity

UVM · AMBA AXI4

AXI4 memory: UVM verification environment

A UVM environment for a memory-mapped AXI4 slave, covering all five channels: write address, write data, write response, read address, and read data.

Verified behavior

  • VALID/READY handshakes
  • Independent AW/W timing
  • Backpressure
  • WSTRB byte strobes
  • BRESP and RRESP responses
  • Reset behavior
  • Read-after-write data integrity

How results are checked

A scoreboard keeps a reference memory and checks read data against it. Functional coverage tracks transactions, handshakes, address and data values, responses, and protocol scenarios.

Source: github.com/mirza1801/axi4_uvm

SystemVerilog · Class-based testbench

Synchronous FIFO: class-based verification environment

A layered, class-based testbench for a parameterized synchronous FIFO, using directed and randomized tests, coverage, assertions, and waveform analysis.

Conditions verified

  • Reads and writes
  • Simultaneous read and write
  • Full and empty flags
  • Overflow and underflow
  • Boundary conditions

Testbench flow

  1. transaction
  2. generator
  3. driver
  4. FIFO (DUT)
  5. monitor
  6. scoreboard
