UVM · AMBA AXI4

AXI4 memory: UVM verification environment

A UVM environment for a memory-mapped AXI4 slave, covering all five channels: write address, write data, write response, read address, and read data.

Verified behavior

  • VALID/READY handshakes
  • Independent AW/W timing
  • Backpressure
  • WSTRB byte strobes
  • BRESP and RRESP responses
  • Reset behavior
  • Read-after-write data integrity

How results are checked

A scoreboard keeps a reference memory and checks read data against it. Functional coverage tracks transactions, handshakes, address and data values, responses, and protocol scenarios. The recorded VCS run reached 98.15% functional coverage with 0 UVM errors across 12 directed scenarios; the repository includes run, regression, and coverage scripts.

Source: github.com/mirzamalikbaig/axi4_uvm

SystemVerilog · Clock domain crossing

Asynchronous FIFO: Gray-coded pointers, scoreboard, and assertions

A 16-entry, 8-bit FIFO with separate write and read clocks. Gray-coded pointers cross between the clock domains through two-flop synchronizers. A self-checking scoreboard, six SVA checks, and seven directed tests verify it. This is a learning project, run with Verilator and a Python regression script.

Source: github.com/mirzamalikbaig/async_fifo

Seven directed tests

  • Fill, check full, then read and compare every value
  • Write one value, read it, check empty
  • Writes while full are blocked and stored data stays correct
  • Reads while empty are blocked
  • Fill and drain four times so the pointers wrap
  • Concurrent writes and reads
  • Reset with pending data, then a new fill and drain

Clock domain crossing

  1. binary pointer
  2. Gray code
  3. two-flop synchronizer
  4. full and empty flags
